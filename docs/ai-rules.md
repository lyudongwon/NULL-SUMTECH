# AI 작업 규칙

> 단기 해커톤용 초안이다. 사전 승인과 사전 검토를 줄이고, **사후 보고와 빠른 테스트·수정**으로 막는다. **(제안)** 표시는 팀 합의 전 값이다. 행사 기간이 끝나거나 프로젝트를 이어가게 되면 검토 규칙을 다시 정한다.

이 파일이 AI 에이전트 규칙의 유일한 원본이다. `CLAUDE.md`는 여기를 가리키기만 한다. 규칙을 바꿀 때는 이 파일만 고친다. Git 관련 세부는 [git-convention.md](git-convention.md)가 우선한다.

## 진행

1. **질문은 막힐 때만 한다.** 작업자, 이슈, 기능 ID는 브랜치명, `progress.md`, 대화에서 추정해 진행하고 가정은 보고에 적는다. 확인하지 못한 값(날짜, 번호, 담당자, 정책 수치, 검증 결과)은 지어내지 않고 `TODO(확인)`로 남긴 채 나머지를 계속한다.
2. **흐름 하나를 끝까지 한다.** `docs/scenarios.yaml`의 흐름(id) 하나를 동작시킨 뒤 커밋하고 다음으로 간다. 다듬기보다 동작하는 것을 먼저 낸다.
3. **막히면 우회한다.** 30분(제안) 넘게 막히면 단순한 대안으로 우회하고 `TODO`로 남긴다.

## 근거와 문서

4. **코드는 레포 문서를 기준으로 쓴다.** 작업과 관련된 문서 1개를 읽으면 시작해도 된다(`CLAUDE.md`의 문서 지도 참고). 채팅이나 회의에서 정한 결정은 [decisions.md](decisions.md)에 한 줄로 남긴다. 노션과 레포가 어긋나면 레포 기준으로 진행하고 어긋난 위치를 보고한다.
5. **계약을 바꿔도 멈추지 않는다.** API, ERD, 에러 코드, 정책을 바꿔야 하면 문서와 코드를 같은 커밋에서 고친다. 보고와 PR 맨 위에 "계약 변경"이라고 적어 팀원이 알게 한다.
6. **구현 여부는 코드와 설정을 읽어 확인한다.** PR 설명은 근거가 아니다. 문서 위치는 줄 번호 대신 `문서 > 섹션 > 문구`로 적는다. 예: `problem.yaml > features > REQ-3`

## 테스트와 수정 (사전 검토 대신)

7. **구현 직후 직접 실행해 확인한다.** 흐름은 시나리오 E2E로, 로직이 복잡한 곳(3단계 판정 규칙)은 단위 테스트로, 나머지는 실제 화면으로 본다. 실행하지 않은 것은 "됨"이라고 하지 않는다.
8. **실패하면 고치고 다시 실행한다.** 실패한 테스트를 지우거나 `skip`·mock으로 우회해 통과시키지 않는다.
9. **`main`은 데모 가능한 상태로 둔다.** CI가 깨지면 원인 분석보다 revert를 먼저 하고, 고친 뒤 다시 올린다.
10. **검토를 미룬 것은 적어 둔다.** 미확인 가정, 임시 처리, 못 돌린 테스트는 `progress.md > 7. 최종 검증 > 아직 못 한 일 / 제한 / 다음 행동`에 적어 후속 테스트 때 소화한다.

## Git과 보고

11. **작은 단위로 자유롭게 커밋한다.** 작업 브랜치 push와 PR 생성은 승인 없이 한다. `main` push는 로컬 테스트를 통과한 뒤에 한다. 상세는 [git-convention.md](git-convention.md)를 따른다.
12. **작업이 끝나면 네 줄로 보고한다.** 한 일 / 실행한 검사와 결과(실제 실행한 것만) / 가정한 것 / 후속 확인 필요.

## 속도보다 먼저 묻는 것

13. 아래는 먼저 묻고 한다.
    - 비밀값(키, 토큰, 비밀번호)을 파일, 커밋, 이슈, PR 어디에도 쓰지 않는다. `.env`는 커밋하지 않고 `.env.example`에는 변수 이름만 둔다.
    - force push, 브랜치·파일 삭제, 남의 변경 덮어쓰기
    - 팀 AI 예산($10 한도)을 크게 쓰는 반복 호출
    - 배포 URL·대시보드 같은 외부에 보이는 설정 변경

## 언어

14. 사용자에게는 한국어로 답한다. 커밋·이슈·PR도 한국어로 쓰되 타입, 코드 식별자, 경로는 그대로 둔다.

## 저장소 약속

15. **기능은 `features`가 먼저다.** 새 기능은 `docs/problem.yaml`의 `features`에 먼저 추가하고, `docs/scenarios.yaml`은 그 기능 ID에 맞춘다.
16. **화면 이름을 바꾸면 같은 커밋에서 맞춘다.** 메뉴·버튼 이름이 바뀌면 `docs/scenarios.yaml`의 `steps`와 `expected`도 함께 고친다.
17. **`progress.md`는 저장소 루트에 둔다.** `docs/` 아래로 옮기지 않는다.
18. **큰 데이터 파일과 빌드 산출물은 커밋하지 않는다.** `.gitignore`를 따른다.
