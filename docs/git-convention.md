> 초안. **(제안)** 표시는 팀 합의 전 항목이고, 표시가 없는 항목은 기존 커밋 이력과 `progress.md`의 약속을 옮긴 것이다. 합의되면 표시를 지운다. 단기 해커톤 방침([ai-rules.md](ai-rules.md))에 맞춰 승인과 리뷰를 기다리지 않고, 테스트와 revert로 `main`을 지킨다.

## 기본 정보

- 저장소: https://github.com/lyudongwon/NULL-SUMTECH (private)
- 기본 브랜치: `main`
- CI와 자동 배포를 연결할 예정이다(`progress.md` 3단계). 연결된 뒤에는 `main`에 들어간 커밋이 곧 배포 대상이므로, `main`은 항상 실행과 테스트가 통과하는 상태로 둔다.

## 브랜치

- **(제안)** 코드 변경은 작업 브랜치에서 하고 PR로 합친다. 문서·설정처럼 작은 변경은 로컬 확인 뒤 `main`에 직접 push해도 된다.
- **(제안)** 이름은 `타입/짧은-영문-설명`으로 쓴다. 예: `feat/photo-upload`, `fix/health-check`, `docs/git-convention`
- 작업 브랜치는 최신 `main`에서 만들고 오래 끌지 않는다.
- 브랜치 삭제는 먼저 묻는다.

## 커밋

형식은 `타입: 한글 요약`이다.

| 타입 | 언제 |
| --- | --- |
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `refactor` | 동작을 바꾸지 않는 코드 구조 변경 |
| `test` | 테스트 추가·수정 |
| `docs` | 문서 추가·수정 |
| `chore` | 빌드·설정·의존성 등 위에 속하지 않는 것 |

- 커밋은 승인 없이 작은 단위로 자주 한다. 잘못 만든 커밋은 되돌리면 된다.
- **한 커밋에는 한 종류만 담는다.** 작업 중 버그를 발견하면 `fix:` 커밋으로 따로 남긴다.
- **예외:** 화면의 메뉴·버튼 이름을 바꿀 때는 `docs/scenarios.yaml`의 흐름도 같은 커밋에서 고친다. API·ERD 같은 계약을 바꿀 때도 문서와 코드를 같은 커밋에서 고친다.
- 요약은 한 줄로 쓰고 끝에 마침표를 찍지 않는다. 관련 기능이 있으면 ID를 넣어도 된다(`REQ-3` 등).
- 왜 바꿨는지는 본문에 적는다. 본문은 선택이다.
- 커밋하기 전에 `git status`와 `git diff`로 담길 파일을 스스로 확인한다. `git add -A`나 `git add .` 대신 파일을 지정해서 추가한다.

예시 (앞의 둘은 실제 이력, 뒤의 둘은 형식을 보이기 위한 예시):

```text
docs: 팀 기능 명세 문서 기준으로 features F1~F11 재작성
docs: 대안 4(글로벌 식품 성분 분석 앱) 삭제
feat: 메뉴판 사진 업로드 API 추가
fix: /__health가 로그인 없이 200을 반환하도록 수정
```

## Pull Request

- **(제안)** 제목은 커밋과 같은 `타입: 한글 요약` 형식으로 쓴다.
- **(제안)** 본문에는 무엇을·왜 바꿨는지, 관련 기능 ID, 확인한 방법(테스트나 화면)을 적는다. API·ERD·에러 코드·정책을 바꿨다면 맨 위에 "계약 변경"이라고 적는다.
- **(제안)** CI가 통과하면 승인을 기다리지 않고 바로 합친다. 리뷰는 합친 뒤 코멘트로 받고, 고칠 것은 후속 커밋으로 반영한다.
- 합치는 방식(squash 또는 merge commit)은 팀이 정한다. 정해지면 여기에 적는다.

## 작업 흐름

1. 시작하기 전에 `git status`로 남은 변경이 없는지 확인한다. 있으면 먼저 커밋하거나 `git stash`로 치운다.
2. `stash`를 썼다면 작업을 마친 뒤 `git stash pop`으로 되돌린다. 충돌이 나면 임의로 해결하지 말고 멈춰서 팀에 알린다.
3. 최신 `main`을 받아 작업 브랜치를 만든다.
4. 관심사별로 커밋하고 push한 뒤 PR을 연다. 모두 승인 없이 한다.
5. CI가 통과하면 합친다.

## main이 깨졌을 때

CI가 깨지거나 배포가 실패하면 원인 분석보다 `git revert`로 먼저 되돌려 `main`을 복구한다. 그다음 작업 브랜치에서 고쳐서 다시 올린다. `reset`과 force push는 쓰지 않는다.

## 하지 않는 것

- `main`에 force push 하지 않는다.
- 남의 변경을 덮어쓰지 않는다. 필요하면 먼저 묻는다.
- 비밀값(`.env`, 키, 토큰, 비밀번호)을 커밋하지 않는다. 실수로 올렸다면 해당 키부터 폐기하고 팀에 알린다.
- IDE 설정(`.idea/`), 빌드 산출물, 큰 데이터 파일을 커밋하지 않는다.
